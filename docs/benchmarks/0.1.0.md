# 0.1.0 索引基准

## 目的

验证 `0.1.0` 在大型本地 Codex 会话库上的索引体积、同步耗时与典型查询延迟，并为后续版本提供可重复基线。

## 运行方式

先构建 release 二进制，再选择一个全新的索引目录：

```bash
cargo build --release
python3 scripts/benchmark_index.py \
  --binary target/release/codex-threads \
  --sessions-dir ~/.codex/sessions \
  --index-dir /tmp/codex-threads-0.1.0-benchmark \
  --thread-query codex-threads \
  --message-query restore-app-thread \
  --event-query function_call_output
```

脚本不会删除已有索引；目标目录已经包含 `threads.sqlite3` 时会拒绝执行，除非显式添加 `--reuse`。

## 0.0.6 基线

基于 2026-07-29 的本地会话库：

- 原始会话：约 1,330 个文件，3.8 GB
- 已索引：1,128 个线程、55,474 条消息、591,038 条事件
- 索引目录：约 3.0 GB
- `threads search codex-threads --limit 5`：约 7.28 秒，回退到 `LIKE`

SQLite 页占用显示，主要重复来自普通表与 FTS content 表同时保存正文：

- `events`：704.6 MB
- `events_fts_content`：279.2 MB
- `threads`：324.6 MB
- `threads_fts_content`：324.4 MB
- `messages`：161.1 MB
- `messages_fts_content`：137.8 MB

## 0.1.0 结果

在 2026-07-29 使用同一会话目录、release 二进制和全新临时索引运行上述命令：

- 原始会话：1,331 个文件，4,102,492,311 字节（约 3.82 GiB）
- 已索引：1,265 个线程、58,629 条消息、361,540 条事件
- v2 索引目录：588,685,484 字节（约 561 MiB）
- 完整重建墙钟时间：24.075 秒，失败文件 0
- `threads search codex-threads`：FTS literal，6 ms，墙钟 0.011 秒
- `messages search restore-app-thread`：FTS literal，4 ms，墙钟 0.009 秒
- `events search function_call_output`：FTS literal，96 ms，墙钟 0.101 秒

相较旧版约 3.0 GB 索引，本次实测索引目录缩小约 80%；同一线程关键词查询由 7.28 秒的 `LIKE` 回退变为 6 ms 的 FTS 查询。旧基线与新结果的已索引线程数不同，体积对比因此按实际目录总量表达，不作为逐行压缩率。

结果来自本机真实历史库，绝对耗时会随硬件、文件系统缓存和会话内容变化；`scripts/benchmark_index.py` 用于在后续版本复跑同一口径。
