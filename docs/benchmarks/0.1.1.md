# 0.1.1 检索补充信息基准

2026-09-23 在同一台 macOS arm64 机器上，比较 Homebrew 的 0.1.0 release 二进制与本次 0.1.1 release 构建。取最近 100 个会话文件复制为固定快照，两个版本分别创建全新索引，不修改用户现有索引。原始内容和原始测量 JSON 留在本地，不提交私人历史。

## 索引与同步

| 指标 | 0.1.0 | 0.1.1 |
| --- | ---: | ---: |
| 快照文件数 | 100 | 100 |
| 原始字节数 | 298,622,487 | 298,622,487 |
| 索引字节数 | 48,877,740 | 48,877,740 |
| 会话 / 消息 / 事件 | 97 / 3,035 / 17,547 | 97 / 3,035 / 17,547 |
| 完整同步墙钟时间（秒） | 1.907 | 1.600 |
| 失败文件 | 0 | 0 |

文件数与会话数不同，表中按实际扫描文件数和索引记录数分别记录。同步为每版本一次，不把墙钟时间差解释成性能提升。

## 查询

每项查询 `--limit 20`，重复七次取中位数；均命中 20 条，使用 FTS literal。进程墙钟包含启动和 JSON 输出。

| 查询 | 0.1.0 内部 / 墙钟 ms | 0.1.1 内部 / 墙钟 ms |
| --- | ---: | ---: |
| threads search codex-threads | 6 / 9.89 | 7 / 10.70 |
| messages search codex | 9 / 13.06 | 9 / 13.78 |
| events search function_call_output | 1 / 4.37 | 1 / 4.50 |

本次新加的范围信息只读索引中的会话计数、重建标记和可选的会话存在性，不扫描原始目录；这份样本未出现明显查询退化。结论仅适用于此快照，不替代大型库的覆盖测试；毫秒级差异会受缓存及系统负载影响。

## 复跑方式

保存新旧二进制，对同一个静止会话快照分别执行：

```bash
python3 scripts/benchmark_index.py \
  --binary /path/to/version/codex-threads \
  --sessions-dir /path/to/fixed-snapshot \
  --index-dir /path/to/new-index \
  --thread-query codex-threads \
  --message-query codex \
  --event-query function_call_output
```

两个版本使用不同的空索引目录。随后分别重复以上三条搜索七次，从 JSON `duration_ms` 和进程墙钟取中位数。不要直接用持续写入的会话目录进行前后对比。公开可复现的正确性样本见 [固定检索验收](../retrieval-validation.md)。
